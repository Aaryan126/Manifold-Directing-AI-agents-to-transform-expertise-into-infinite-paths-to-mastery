## Confirmed Architecture Decisions

*(Record finalized architecture choices here with a one-line rationale and date. This section is the record `AGENTS.md` uses to keep `prd.md` Section 8 in sync if the real stack diverges from the recommendation.)*

- 2026-07-11: LLM provider/model is OpenAI GPT-5.4 for all LLM-powered agents (segmentation, concept-graph building, clip extraction/classification, assessment generation, and dashboard diagnosis) so the project uses one consistent reasoning model across the AI pipeline.
- 2026-07-11: Graph storage is Postgres adjacency tables with DAG validation and recursive CTE traversal, behind a graph repository/service boundary so a future move to a dedicated graph DB is not invasive.
- 2026-07-11: ASR starts with OpenAI transcription behind a strict provider abstraction so pipeline code does not depend directly on one vendor's API shape.
- 2026-07-11 (implemented 2026-07-12): Video delivery is Mux for production, with a local adapter for development and CI. The implemented provider uses Mux Direct Uploads, polls asset creation, persists public playback IDs, reports/enforces the 10-video Free Plan cap, and remains selected only when `VIDEO_PROVIDER=mux` with credentials.
- 2026-07-12 (entry flow revised 2026-07-21): Development identity is an explicitly non-production user context with persisted instructor/learner roles. A fixed-credential development login now selects that context and routes into the matching Course OS; real password storage, signed sessions, recovery, account administration, and production authentication remain deferred.
- 2026-07-12: Production UI foundation is Tailwind CSS v4 plus shadcn/ui Nova with Base UI primitives, Lucide icons, self-hosted Instrument Sans/Source Serif 4, and semantic OKLCH design tokens. This supports the approved staged redesign while keeping component source local and auditable.
- 2026-07-21: Agent orchestration will use a durable Postgres-backed task queue and an in-process FastAPI worker with leases, retries, and restart recovery. This keeps the current Render/Neon deployment topology while moving generation ownership out of the browser.
- 2026-07-21: Published-course editing will use versioned working revisions with stable logical artifact identities. Publishing an update preserves completed learner work and maps future routing onto the new revision rather than mutating learner history.
- 2026-07-21: Course intelligence remains deterministic and evidence-first, while GPT-5.4 may explain evidence and prepare typed changes. Course Director is the single conversational coordinator; persisted Learning Analyst, Curriculum Architect, Clip Editor, and Assessment Designer activity makes specialist work visible without creating competing chat surfaces.
- 2026-07-21: The cross-course dashboard assistant uses deterministic persisted-evidence retrieval followed by GPT-5.4 structured synthesis with validated evidence IDs. The model may classify and target a requested change, but execution still creates only a private Course Director proposal; a grounded local adapter exists for tests and environments without an API key.
- 2026-07-21: Supplemental PDF/PPTX material uses revision-aware Postgres source records, page/slide extraction and citations, PostgreSQL full-text retrieval, and selective GPT-5.4 vision analysis for image/diagram-heavy pages. Documents default to private AI context and require explicit review plus publication before learner visibility.
- 2026-07-22: The Phase 11 Blueprint remains on React Flow and adds ELK.js only for visible-subgraph auto-layout. The existing Postgres adjacency model remains authoritative; no graph database, embedded n8n/H5P runtime, or Bayesian Knowledge Tracing dependency is introduced. Mastery stays evidence-first until real calibration data justifies a probabilistic model.
- 2026-07-22: Adaptive sequencing is explicit and revisioned through `concepts.sequence_rank`; prerequisite eligibility is a hard constraint, instructor sequence breaks eligible ties, and learner evidence controls remediation or reinforcement. Questions gain explicit many-to-many concept coverage and each routed attempt emits an immutable route event.
- 2026-07-24: The primary Blueprint is the detailed free-form all-artifact React Flow graph with initial fit-to-view, saved instructor positions, topic-neighborhood focus, and synchronized outline/inspector controls. This follows direct human preference testing; the structured swimlane renderer is no longer a product destination.
- 2026-07-24: Blueprint readability will stay on React Flow + ELK and use typed custom nodes, fixed semantic ports, ELK orthogonal bend-point routing, deterministic sequence-aware layers, and core-path progressive disclosure. This preserves the selected free-form workspace and existing Postgres graph contract while reducing visual ambiguity and edge crossings without another graph dependency.
- 2026-07-24: Blueprint Design authoring uses a type-aware mutation contract over the existing revisioned Postgres artifacts rather than embedding a generic workflow editor. Direct instructor changes are audited private-revision mutations; optional AI cleanup uses the surrounding course graph and evidence to prepare a bounded proposal pack whose artifacts remain independently `Accept / Edit / Dismiss` reviewable.
- 2026-07-24: Manual Blueprint authoring and Course Director use the same validated typed mutation vocabulary. Manual actions may mutate only the private working revision and are audited immediately; conversational actions are prepared as a bounded, ordered change plan and require independent `Accept / Edit / Dismiss` decisions before the same mutation handlers run. Relationship creation is an explicit source → meaning → valid-target flow rather than raw React Flow handle semantics.
- 2026-07-25: A course is revisioned at two connected levels. The new Course Flow is the default high-level graph and contains optional module swimlanes with only lecture, standalone quiz, and assignment units; a lecture opens the existing detailed Blueprint of topics, concepts, clips, questions, sources, and remediation. Both levels publish atomically and Course Director uses the same server-side mutation services as manual authoring.
- 2026-07-25: Standalone quizzes own reviewed concept-grounded questions, while embedded checks remain owned by lecture topics. Assignments initially provide reviewed instructions, concept/source coverage, learner completion, and routing participation without file submissions or grading.
- 2026-07-25: Course creation and lecture creation are separate persisted actions. The dashboard creates a named course container without fabricated content and now supplies a per-dialog idempotency key backed by a database unique index, so a retry returns the original course without creating another revision or conversation. Course Flow owns full lecture URL/file ingestion and durable lecture-scoped generation; opening or leaving lecture intake never creates a course. Course-level navigation contains only Course Flow plus a compact global routing-settings popover, while a selected lecture exposes its contextual Blueprint, Assessments, and Preview. Course Flow relationship authoring uses the same source → meaning → valid target contract as lecture Blueprint instead of a generic toolbar dialog.
- 2026-07-26: Phase 13's Learning Assistant is a deterministic, bounded in-course action service rather than a free-form tutor. It may plan and reorder reviewed artifacts, explain persisted routing evidence through templates, reveal reviewed hints, record learner-owned goals/reflections, and create structured help requests; it may not generate teaching claims, examples, questions, hints, or remediation at learner runtime.
- 2026-07-26: The learner Learning Assistant uses a Course Director-style persisted conversation dock. GPT-5.4 may classify a learner's free-text intent into an allowlisted action, but learner-visible replies are rendered from deterministic platform guidance, persisted progress, routing evidence, and instructor-reviewed artifacts. This provides natural-language control without creating an unreviewed generative tutor.
- 2026-07-26: Learner mastery/review uses a read-only React Flow + ELK prerequisite map with deterministic course-sequence context. Solid links express true prerequisites, subtle dashed links preserve sequence orientation only where no prerequisite link exists, and nodes expose recommendation/readiness/mastery/content states with a separate evidence inspector. This reuses the established graph stack while keeping learner actions bounded by prerequisite and reviewed-content eligibility.
- 2026-07-26: Placement reuses each concept's instructor-reviewed routing policy. Distinct reviewed primary questions must satisfy the configured correct-attempt and confidence thresholds before placement may mark a concept mastered; low-confidence correct evidence may mark it practiced, and an incorrect placement answer retains the concept without downgrading prior mastery.
- 2026-07-26: Review scheduling is deterministic rather than probabilistic: first review seven days after mastery, then 21 and 60 days after confident-correct reviews, three days after correct-low-confidence evidence, and one day after incorrect review evidence. Learner reflection never changes mastery.
